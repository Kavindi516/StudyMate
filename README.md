# StudyMate

**Smart Study Planner, Group Coordinator & Location-Based Attendance**
iOS Application Development — BSCCOMP25.1P — National Institute of Business Management (NIBM)
Name: N.M.J.K Nanayakkara — Nibm Index: COBSCCOMP251P-014

StudyMate is a native SwiftUI iOS app that helps students plan their studying, coordinate with classmates, and automatically record attendance at lectures. It combines intelligent planning (an on-device Core ML recommender driven by the user's own deadlines) with verifiable, sensor-backed attendance (geofencing confirmed by a short-lived QR / NFC token).

---

## Features

- **Onboarding** — a first-launch introduction to the app's main features.
- **Authentication** — email/password sign-in and sign-up via Firebase Authentication, with an optional Face ID lock.
- **Home dashboard** — time-aware greeting, a smart study-suggestion card, and summary tiles (today / planned / done).
- **Study sessions** — create, complete and delete sessions stored in Core Data, each optionally mirrored to the system calendar via EventKit.
- **Schedule & Calendar** — an ordered session list and a calendar read-back view.
- **Deadlines** — coursework and exam deadlines with a colour-coded countdown (overdue / due soon / comfortable).
- **Location-based attendance** — class locations on a MapKit map with geofence circles; one-tap check-in when inside the geofence.
- **Secure check-in** — a refreshing QR code / NFC token (valid 60 seconds) generated by the group leader; validated against freshness **and** geofence.
- **Study groups** — create or join groups with a share code, synced in real time via Firebase Firestore.
- **Statistics** — study hours by subject and attendance, rendered with Swift Charts.
- **Smart recommender** — an on-device Core ML model suggesting which subject to study next.
- **System integration** — App Intents (Siri/Shortcuts), local notifications, a Home Screen widget, and a light/dark theme toggle.

## Architecture

The app follows **MVVM** with a dedicated services layer.

```
StudyMate/
  StudyMateApp.swift            App entry point
  Models/                       StudyGroup, GroupSession, AttendanceToken
  ViewModels/                   AuthViewModel, GroupDetailViewModel
  Services/                     Auth, Location, Calendar, Notification, NFC,
                                Attendance, Group, ML, Recommendation,
                                Persistence (Core Data), WidgetUpdater, SharedStore,
                                StudyMateLogic (pure, testable core)
  Views/                        SwiftUI screens + DesignSystem/CardStyle (shared look & feel)
  Intents/                      App Intents (Add Study Session, Next Session, Shortcuts)
  ML/                           StudyRecommender.mlmodel (Create ML)
  Resources/                    Core Data model, GoogleService-Info.plist
StudyMateWidget/                Home Screen widget
StudyMateTests/                 Unit tests (Swift Testing)
StudyMateUITests/               UI tests (XCUITest)
```

- **Local-first data:** Core Data persists sessions, deadlines, class locations and attendance, so planning works offline. Only the collaborative group features require connectivity.
- **Shared validation core:** `StudyMateLogic` holds pure functions (attendance %, countdowns, token freshness, geofence maths) that are unit-tested directly.
- **Design system:** a single `Theme` (brand gradient, `softCard` modifier, priority/countdown colours) keeps the UI consistent across every screen and both appearances.

## Requirements

- Xcode (iOS 17+ SDK recommended)
- Swift Package Manager (dependencies resolve automatically on first open)
- A Firebase project (`GoogleService-Info.plist` is included)

## Build & run

1. Open `StudyMate.xcodeproj` in Xcode.
2. Wait for Swift Package Manager to resolve Firebase (11.15.0).
3. Select the **StudyMate** scheme and an iPhone or iPad simulator.
4. Press **⌘R** to run. To run tests, press **⌘U**.

## Known limitations

- **Home Screen widget (live data):** the widget is implemented and writes the next session, but live data sharing needs an **App Group**, which requires a paid Apple Developer account. Without one the entitlement can't be provisioned, so the widget falls back to a static display.
- **NFC:** Core NFC is iPhone-only and needs a physical device; on the simulator and on iPad the app falls back to QR and geofence check-in.
- **QR scanning on simulator:** the iOS Simulator has no camera, so the scan path is tested via the geofence path and a manual code-entry option; QR generation/scanning is demonstrated on screen.
- **Firestore rules:** currently in development mode for assessment, not production-hardened.

## Reflection

Building StudyMate deepened my understanding of SwiftUI's adaptive, size-class-driven layout (one codebase running on both iPhone and iPad), of structuring a mobile app with MVVM and a clean services layer, and of integrating multiple Apple frameworks around a single real-world problem — turning location, a time-limited token, and a local ML model into trustworthy attendance and useful study suggestions. The main challenges were dependency stability (resolved by pinning Firebase to 11.x) and working within the constraints of a free developer account (App Groups / live widget). Testing early and keeping core logic in a pure, isolated layer made the app far easier to verify and to reason about.
